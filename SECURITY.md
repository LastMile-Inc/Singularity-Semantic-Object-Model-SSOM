# Security Disclosure

This repository includes semantic models and example artifacts that may describe cybersecurity, operational, or workflow-sensitive contexts. Do not disclose sensitive repository issues by opening a public issue when the report could expose private operational detail.

## How to report

- Report security-sensitive findings privately to the maintainer.
- Include the affected artifact, a concise impact statement, and the minimum evidence needed to reproduce the concern.
- Do not disclose credentials, secrets, live tenant data, or exploit detail in the initial report.

## Handling expectations

- The maintainer coordinates review and remediation.
- Coordinated handling is expected before public disclosure.
- The repository may publish a sanitized follow-up note after remediation when public documentation is appropriate.

## Scope note

This document describes repository disclosure workflow only. It does not create legal guarantees or incident-response commitments beyond coordinated maintainer review.
