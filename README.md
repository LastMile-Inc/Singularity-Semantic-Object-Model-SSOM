# SSOM RFCs

The **Standardized Semantic Object Model (SSOM)** is an open, vendor-neutral, AI-native semantic standard for operational technology and industrial operations data.

SSOM standardizes **meaning**, not transport, control behavior, workflow execution, dashboard behavior, cloud deployment, or vendor-specific product implementation.

## Why SSOM exists

Operational data is generated by many systems, facilities, equipment types, platforms, and vendors. It is often difficult to use across those boundaries because it lacks:

- Shared semantic meaning
- Portable asset identity
- Explicit relationships and topology
- Provenance and source authority
- Quality and temporal context
- A consistent, machine-readable representation suitable for analytics and AI

SSOM addresses that gap by defining a common semantic model for operational facts.

## What SSOM standardizes

- Assets
- Relationships and topology
- Observations and telemetry
- Events and alarms
- Conditions
- Operational context
- Provenance and lineage
- Quality and confidence
- Temporal integrity
- Policy evidence
- Extensions, profiles, compatibility, and conformance

## What SSOM does not standardize

SSOM does not replace or define:

- MQTT, Sparkplug, OPC UA, REST, Kafka, AMQP, Modbus, BACnet, or other transports or protocols
- SCADA, BMS, MES, historians, brokers, Industrial DataOps products, OEM systems, or control systems
- PLC logic or direct process-control commands
- Workflow engines, task queues, approvals, assignments, or case-management products
- User accounts, tenant administration, billing, credentials, support, or product configuration
- Dashboard layouts, widget models, UI state, or visualization frameworks
- A mandatory database, cloud provider, event bus, or serialization implementation
- Any requirement to share data with a third party
